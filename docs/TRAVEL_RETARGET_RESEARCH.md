# 順番待ち中の移動先切替調査

2026-10-23。開発版1.4.1.16 / 1.4.1.7_jp_min.10に実装。公開版1.4.1.15とインストール済み版は変更していない。

## 確認した根拠

- ローカルのLifestream配置はinstalledPlugins/Lifestream/2.6.0.8。
- 上流IPCProviderのAbortはTaskManager.AbortとfollowPath.Stop。ゲーム側のワールド移動予約解除はこの関数には含まれない。
- ローカル固定ECommonsのUIHelpers/AddonMasterImplementations/WorldTravelFinderStatus.csには出発・行先・順番の文字列取得と、ボタンID13をClickButtonIfEnabledで押すCancelがある。現在のゲームでこの操作が予約解除を完了することは未検証。
- HuntAlertsのExecuteTeleportは共有CancellationTokenSourceとIsTaskRunningを使用する。既存の再クリック中止はrunningを早期解除するため、単純に新しい移動を続けて起動すると旧処理のfinallyと競合する可能性がある。

上流根拠：https://github.com/NightmareXIV/Lifestream/blob/main/Lifestream/IPC/IPCProvider.cs
上流mainとインストール済みDLLの同一性は未確認。

## 実装条件

1. HuntAlertsがChangeWorldを受理された移動だけを出発ワールド・行先とともに追跡する。実装は単一の実行スロットを旧処理のfinallyまで保持する方式であり、要求ID方式は採用しない。
2. ロード中でなく元ワールドにいて、待機画面の行先が自分の要求と一致しキャンセル可能な場合だけ切替を受け付ける。
3. 旧HuntAlerts処理へ取消を通知し、Lifestream.Abortとゲームの待機予約解除を同じFrameworkスレッドから要求する。旧処理の終了は新しい移動開始前に待つ。一般的なYes/No画面は操作しない。
4. 予約解除・同じ出発ワールド・非ロード中・Lifestream停止を確認してから最後に選ばれた要求だけを実行する。
5. キャンセル画面消失だけを成功判定にしない。移動開始による画面消失と区別できなければ停止・理由表示とする。
6. 外部開始の移動、行先不一致、別DC移動、解除失敗やタイムアウトは自動切替しない。

## 実装した判定と制約

- 日本語クライアントのみ対応。元のSystemMessage・空の送信者・「申請が取り消されました。」の完全一致を確認する。チャットの他チャンネルやプラグインによる本文変更は採用しない。
- 転送予約状態（WorldTravelFinderStatus）を表示していることが必要。HUDだけでは取消しない。既知AtkValuesの型・件数、出発/行先、正の待機順位、取消ボタンの表示/有効状態、WaitingToVisitOtherWorldを要求する。
- 取消ログだけでは再申請しない。予約画面消失、待機フラグ解除、元ワールド、非ロード、旧ルーチン終了、Lifestream非busyをすべて確認し、500ms安定した後に最後の選択先へ移動する。
- 取消要求から15秒で確認できなければ理由を表示して停止。ログアウト・ロード・元ワールドからの移動・連携OFF・IPC例外でも再申請しない。取消再送・強制的な再Abort・Yes/No承認は行わない。
- 日本語以外のクライアントや別DCへの切替は、取消操作前に拒否。新規の通常移動は従来の同一リージョン条件を維持する。
- 旧ルーチンの取消直後にrunningを解除する競合を修正。Frameworkへ予約済みのテレポ/地図操作もトークンを再確認する。アンロード時はイベント解除と自分のルーチン取消のみ行い、外部プラグインへAbortしない。
- 手動取消ログを受信した場合は追跡を破棄して自分の旧ルーチンを止める。外部の予約やLifestream全体に所有権トークンはないため、他ツールとの同時操作を完全に識別できる保証はない。同一行先への外部再申請などは同時に行わないこと。
- エーテライトIDなしで既存ルーチンが終了した移動は追跡対象外。旧処理が停止しただけで残っている外部busyを無条件解除する復旧機能ではない。
