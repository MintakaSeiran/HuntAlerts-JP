# SS履歴表示・DC移動中の受信保持

対象：HuntAlerts日本語Relay版。プレビュー版 `1.4.1.7_jp_min.4`、DLL/manifest `1.4.1.10`。ユーザーの公開依頼に基づくリリース。実機未確認。

## SSの表示

- 履歴カードと、そこから開く詳細画面の見出しだけをSS判定に対応する。
- AS Mob PlateでACTログから確認済みのSS本体BNpcName ID `0x22D3`、`0x2977`、`0x345E` を使い、同一配布のゲームシートからEN/JP/DE/FRの名前を取得して照合する。外部プラグインへの依存は追加しない。
- 前後空白、大文字小文字、通知元の角括弧による翻訳併記を考慮する。文章の部分一致や「SS」という文字だけでは判定しない。
- 通常S、眷属、名前不明、未対応の名前は従来のS表示を維持する。シート取得失敗はログに残し、照合できない名前をSSへ昇格させない。
- 保存済み履歴にも表示時に適用する。履歴Version、設定Version、IPC型、チャット・Relay・トーストの文章は変更しない。

## DC移動中

従来はSocket.IOで受信していても、ログインしていなければ処理前に破棄していた。新実装ではログイン・プレイヤー・現在ワールド/DCの情報がそろうまで保持する。

- 一時保持は受信順で直近50件。上限超過は最古の保留イベントを捨て、警告ログを残す。
- 復帰後、1フレーム最大5件を処理する。対象DC/ワールド/拡張などの設定はこの時点で判定する。「現在DC」は移動先のDC、「現在ワールド」は移動先のワールドとなる。移動前の現在地は代用しない。
- Snooze中の受信は保持しない。処理時にSnoozeなら従来どおり対象外。
- 採用した移動中のツアー・出現通知は履歴だけへ追加。通知音、チャット、ポップアップ、IPCを後から一括発火しない。復帰後の新しい通知は従来どおり扱う。
- 投稿時刻は元の値を維持。ツアーの2分間重複抑止は受信時刻で比較し、フィルターを通らない通知で採用済みの記録を上書きしない。
- 討伐通知は従来から履歴へ入れていない。今回も履歴対象にせず、移動中の討伐通知を復帰後チャットへ流さない。
- プラグイン停止時に保留は破棄する。記録済み履歴は従来どおり保存する。

接続そのものが切れた期間の通知や、ゲーム終了・プラグイン停止中の通知は回復できない。サーバーから過去ログを取得する機能は今回実装しない。受信できた通知の保持と、通知サーバーによる再送保証は別である。

## 検証と実機確認

ゲーム非依存テストはSS完全一致/通常S/眷属/不明/翻訳併記、プレイヤー不在時の保持、復帰後の順序・時刻・履歴限定フラグ、直前にキューへ入った通知の無音化、50件上限、アンロード時の破棄を検証する。

実機では以下を確認する。ビルド成功だけでは確認済みとしない。

1. 通常SとSS本体の履歴・詳細の見出し。以前に保存したSS通知にも適用されること。
2. DC移動中に実際に受信した通知が、復帰後の履歴へ入ること。元の投稿時刻を維持し、音・チャット・ポップアップ・IPCが再発火しないこと。
3. 「現在DC」「現在ワールド」で移動先だけが採用されること。「設定済み全体」「ホームワールド」の動作、Snooze、対象拡張OFFも確認する。
4. 復帰後の新規通知の音・チャット・ポップアップ・IPCが通常どおり動作すること。
5. 接続診断でSocket.IOの切断があった場合は、未受信区間と保持処理の問題を区別すること。
